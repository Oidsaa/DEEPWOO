# داشبورد ووکامرس — دسکتاپ ویندوز

برنامهٔ دسکتاپ (Electron) برای مدیریت فروشگاه ووکامرس **بدون ورود به پیشخوان وردپرس**؛ کاملاً فارسی و راست‌چین، با ظاهری الهام‌گرفته از داشبوردهای مالی مدرن (Fintech). ارتباط با فروشگاه از طریق **REST API ووکامرس** (نسخهٔ ۳) و فقط با کلیدهای API برقرار می‌شود؛ به همین دلیل برای اتصال به پنل ادمین و حتی وردپرس به لاگین نیازی نیست.

## امکانات (مرحلهٔ نخست)

- منوی **مشتریان**: فهرست کامل مشتریان با جستجوی زنده (نام، ایمیل، شهر)، صفحه‌بندی، شماره‌گذاری فارسی، تاریخ شمسی و خلاصهٔ آماری؛ کلیک روی هر سطر، تاریخچهٔ سفارش‌های همان مشتری را نشان می‌دهد. سه ویجت بالا **سراسری** هستند: تعداد همهٔ مشتریان فروشگاه، مشتریانی که در **ماه جاری شمسی** خرید کرده‌اند و **مجموع خرید همهٔ مشتریان** (طبق قانون برنامه — نه فقط صفحهٔ فعلی و نه فقط سفارش‌های پرداخت‌شده).
- منوی **محصولات**: فهرست محصولات **در همهٔ وضعیت‌ها** (منتشرشده، خصوصی، پیش‌نویس و در انتظار — با فیلتر وضعیت در بالای جدول؛ بدون اسکرول افقی) شامل عکس، قیمت (و قیمت حراج)، وضعیت موجودی، تعداد فروش و دسته‌بندی + جستجو و صفحه‌بندی؛ دکمهٔ «افزودن محصول» برای ساخت محصول جدید (ساده/متغیر). ستون عملیات (همه فقط آیکن): جزئیات/ویرایش ترکیبات، سفارش‌های محصول (بدون احتساب سفارش‌های ناموفق/لغو/بازپرداخت)، تغییر کلی قیمت و تغییر کلی موجودی.
- **ویجت‌های آماری محصولات** (کل/موجود/ناموجود/فروش کل) روی **همهٔ صفحات** محاسبه می‌شوند نه فقط صفحهٔ جاری (داخل برنامه همهٔ صفحه‌های منطبق خوانده و در حافظه جمع می‌شوند)؛ سه ویجت اول کلیک‌پذیرند و فهرست را به همان گروه فیلتر می‌کنند (کلیک دوباره = حذف فیلتر).
- منوی **تنظیمات**: وارد کردن آدرس سایت و کلیدهای API، تست اتصال و ذخیرهٔ امن کلیدها روی خود دستگاه.
- کلیدها فقط در پوشهٔ کاربر (userData) همین سیستم ذخیره می‌شوند و از برنامه خارج نمی‌شوند.
- امضای درخواست‌ها با پروتکل استاندارد OAuth 1.0a (HMAC-SHA1) — کلیدها هرگز در URL ساده ارسال نمی‌شوند.
- **همگام‌سازی خودکار**: بعد از ذخیرهٔ کلیدها، اتصال به‌صورت خودکار بررسی و بلافاصله فهرست واقعی مشتریان بارگذاری می‌شود (و هر بار ورود به «مشتریان» دوباره از فروشگاه خوانده می‌شود).

> **نکتهٔ فنی:** فهرست مشتریان از `wc/v2/customers` خوانده می‌شود نه `wc/v3` — چون نسخهٔ ۳ عمداً فیلدهای `orders_count` و `total_spent` را برنمی‌گرداند و ستون‌های «سفارش‌ها» و «مجموع خرید» به آن‌ها نیاز دارند. بقیهٔ درخواست‌ها (تاریخچهٔ سفارش، افزودن مشتری) روی `wc/v3` می‌مانند؛ هر سایتی که v3 را پاسخ می‌دهد (ماژول Legacy REST API ووکامرس) v2 را هم پاسخ می‌دهد.
>
> **وضعیت محصولات و REST:** API محصولات فقط **یک** مقدار `status` را در هر درخواست می‌پذیرد (لیست چندمقداری مثل `publish,draft` در برخی نسخه‌ها/فروشگاه‌ها با خطای «پارامتر نامعتبر» رد می‌شود). وقتی در برنامه «همهٔ وضعیت‌ها» انتخاب باشد، هر وضعیت به‌صورت موازی واکشی و سپس در حافظه ادغام و مرتب می‌شود (سقف ۱۰۰۰ محصول برای هر وضعیت).
>
> **سفارش‌های یک محصول:** درخواست سفارش‌ها پارامتر `status` را صریحاً نمی‌فرستد (پیش‌فرض خودِ API همهٔ وضعیت‌هاست) تا روی فروشگاه‌های سخت‌گیر رد نشود؛ پس از دریافت، سفارش‌های ناموفق/لغو/بازپرداخت به‌کلی کنار گذاشته می‌شوند — نه در فهرست نمایش داده می‌شوند و نه در «تعداد سفارش‌ها»، «عدد فروخته‌شده» و «مجموع فروش» لحاظ می‌شوند (تعداد حذف‌شده‌ها زیر فهرست یادداشت می‌شود). برای آنکه شمارش دقیق باشد، همهٔ صفحه‌های سفارش همان محصول تا سقف ۲۰۰۰ سفارش خوانده می‌شود.
>
> **وضعیت‌های سفارشی فروشگاه:** وضعیت‌های دلخواهِ ثبت‌شده در فروشگاه هم فارسی نمایش داده می‌شوند (فروش حضوری، تایید فروشگاه، تایید کارگاه، تحویل پیک، تحویل پست، تحویل تیپاکس و هر وضعیت ناشناخته با نام خام خودش).
>
> **جزئیات و ویرایش محصول:** دکمهٔ «جزئیات» در هر ردیف، ترکیبات (متغیرها) را با قیمت، قیمت حراج، موجودی و وضعیت هر ترکیب نشان می‌دهد و اجازهٔ ذخیرهٔ تغییرات هر ترکیب (`PUT …/products/{id}/variations/{vid}`) یا ویرایش محصول ساده (`PUT …/products/{id}`) را می‌دهد — این‌ها به کلید **خواندن/نوشتن** نیاز دارند. واحد «فروش کل» در این بخش «عدد» است.
>
> **تغییرات کلی (عملیات هر ردیف):** دو دکمهٔ «تغییر کلی قیمت» و «تغییر کلی موجودی» در ستون عملیات، به ترتیب قیمت (افزایش/کاهش درصدی با گرد شدن به ۱٬۰۰۰ تومان یا قیمت ثابت) و موجودی+وضعیت را روی **همهٔ ترکیبات** محصول متغیر یا روی خودِ محصول ساده اعمال می‌کنند — هر مورد با یک درخواست جداگانه ذخیره می‌شود (کلید خواندن/نوشتن لازم است). در «تغییر کلی موجودی»، مقدار روی همهٔ ترکیبات ثبت می‌شود و اگر ترکیبی مدیریت موجودی نداشته باشد، به‌صورت خودکار فعال می‌شود تا آن مقدار واقعاً روی همه اعمال شود.
>
> **چیدمان جدول محصولات:** جدول محصولات با `table-layout: fixed` چیده شده تا در هیچ عرض پنجره‌ای اسکرول افقی ایجاد نشود؛ نام و دستهٔ طولانی با «…» بریده می‌شوند و دکمه‌های عملیات در صورت تنگی به ردیف دوم می‌روند.
>
> **مجموع خرید:** ووکامرس فقط سفارش‌های «پرداخت‌شده» (در حال پردازش/تکمیل‌شده) را در `total_spent` می‌شمرد؛ برنامه برای هر مشتری سفارش‌هایش را می‌خواند و مجموع را با احتساب **همهٔ وضعیت‌ها به‌جز ناموفق، لغو شده و بازپرداخت‌شده** محاسبه می‌کند (ستون جدول و خلاصهٔ تاریخچهٔ سفارش‌ها). مقادیر برای هر نشست کش می‌شوند تا پیمایش صفحه‌ها سریع بماند.
>
> **ویجت‌های سراسری مشتریان:** ویجت‌های «کل مشتریان»، «مشتریان ماه جاری» و «مجموع خرید» با پیمایش **همهٔ مشتریان فروشگاه** (در پس‌زمینهٔ فرایند اصلی، با محدودیت همزمانی) محاسبه می‌شوند؛ «ماه جاری» یعنی حداقل یک سفارشِ مشمول‌شمار در ماه جاریِ شمسی. چون هر مشتریِ دارای سفارش یک‌بار خوانده می‌شود، اولین محاسبه در فروشگاه‌های بزرگ چند دقیقه طول می‌کشد (ویجت‌ها تا پایان آن «…» نشان می‌دهند) و پس از آن تا پایان نشست فوری است؛ خواندن ناموفقِ یک مشتری به‌جای شکست کل محاسبه، فقط از عدد نهایی حذف می‌شود.

## ساخت کلید API در ووکامرس

1. در پیشخوان وردپرس: **ووکامرس ← تنظیمات ← پیشرفته ← REST API**.
2. **افزودن کلید**؛ نام دلخواه، دسترسی **خواندن (Read)** و کاربر **کاربر** را انتخاب کنید.
3. مقدارهای `Consumer Key` و `Consumer Secret` را کپی و در بخش «تنظیمات» برنامه وارد کنید.
4. «ذخیره تنظیمات» و سپس «تست اتصال» را بزنید؛ اگر موفق بود، مشتریان در «مشتریان» نمایش داده می‌شوند.

> پیش‌نیاز سایت: افزونهٔ ووکامرس نصب و فعال باشد و API از مسیر استاندارد `/wp-json/wc/v3` در دسترس باشد.

## اجرا در حالت توسعه

```bash
npm install
npm run dev
```

این دستور Vite و پنجرهٔ Electron را با بارگذاری داغ (HMR) اجرا می‌کند.

## ساخت خروجی (تست بدون نصب)

```bash
npm run dist:dir
```

فایل اجرایی در `release/win-unpacked/` ساخته می‌شود.

## ساخت نصاب ویندوز

```bash
npm run dist
```

خروجی: `release/WooCommerce-Dashboard-Setup-0.1.0.exe` (نصاب NSIS؛ امکان انتخاب مسیر نصب).

**نکته:** نصاب امضای دیجیتال ندارد، بنابراین هنگام اجرا ممکن است SmartScreen ویندوز هشدار دهد → «اطلاعات بیشتر ← اجرا به هر حال».

### اگر دانلود ابزارهای بسته‌بندی از GitHub قطع شد

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ \
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ \
npx electron-builder
```

اگر خطای `EPERM` هنگام استخراج Electron در بسته‌بندی دیدید (تداخل آنتی‌ویروس با rename)، از نسخهٔ آمادهٔ Electron استفاده کنید:

```bash
npx electron-builder --config.electronDist=node_modules/electron/dist
```

## ساختار پروژه

```
src/
  main/        فرایند اصلی Electron (پنجره، ذخیرهٔ تنظیمات، کلاینت REST ووکامرس + امضای OAuth)
  preload/     پل امن (contextIsolation) بین رابط و فرایند اصلی
  shared/      تایپ‌های مشترک
  renderer/    رابط کاربری React (فارسی/راست‌چین) + فونت وزیرمتن
scripts/       تولید آیکون برنامه (بدون وابستگی خارجی)
build/         آیکون‌های برنامه (icon.png / icon.ico)
```

# داشبورد ووکامرس — دسکتاپ ویندوز

برنامهٔ دسکتاپ (Electron) برای مدیریت فروشگاه ووکامرس **بدون ورود به پیشخوان وردپرس**؛ کاملاً فارسی و راست‌چین، با ظاهری الهام‌گرفته از داشبوردهای مالی مدرن (Fintech) و **تم روشن/تیره با رنگ تأکیدی دلخواه**. ارتباط با فروشگاه از طریق **REST API ووکامرس** (نسخهٔ ۳) و فقط با کلیدهای API برقرار می‌شود؛ به همین دلیل برای اتصال به پنل ادمین و حتی وردپرس به لاگین نیازی نیست.

## امکانات

### پیشخوان

- خوش‌آمدگویی با **نام کارشناس** (صاحب کلید API همین دستگاه).
- **ساعت زنده** و **تاریخ شمسی** (روز هفته، ماه و سال) به‌همراه **مناسبت‌های رسمی تقویم ایرانی** (نوروز، سیزده‌بدر، روز پزشک، شب یلدا و…).
- دو کارت آماری: **تعداد سفارش‌هایی که خودِ کارشناس ثبت کرده** و **مجموع مبلغ آن‌ها** (از «لاگ تغییرات» با فیلتر `order-create` و فیلد مبلغ خوانده می‌شود).
- **۵ اکشن آخر** همان کارشناس با برچسب بخش (سفارش‌ها/محصولات/مشتریان/انبارها/…) و زمان شمسی، با میان‌بر به «لاگ تغییرات».

### مشتریان

- فهرست کامل مشتریان با جستجوی زنده (نام، ایمیل، شهر)، صفحه‌بندی، شماره‌گذاری فارسی، تاریخ شمسی و خلاصهٔ آماری؛ کلیک روی هر سطر، تاریخچهٔ سفارش‌های همان مشتری را نشان می‌دهد.
- سه ویجت بالا **سراسری** هستند: تعداد همهٔ مشتریان فروشگاه، مشتریانی که در **ماه جاری شمسی** خرید کرده‌اند و **مجموع خرید همهٔ مشتریان** (طبق قانون برنامه — نه فقط صفحهٔ فعلی و نه فقط سفارش‌های پرداخت‌شده).

### سفارش‌ها

- فهرست **همهٔ سفارش‌های فروشگاه** (جدیدترین‌ها در ابتدا) با جستجو بر اساس شمارهٔ سفارش/نام مشتری و صفحه‌بندی.
- **چیپ‌های فیلتر وضعیت** با تعداد هر وضعیت — فهرست وضعیت‌ها **دقیقاً از وضعیت‌های ثبت‌شدهٔ خودِ سایت** خوانده می‌شود (`reports/orders/totals`)، پس وضعیت‌های سفارشی فروشگاه (فروش حضوری، تایید کارگاه، تحویل پیک/پست/تیپاکس و…) هم با نام و برچسب رنگی خودشان دیده می‌شوند.
- هر ردیف: چک‌باکس انتخاب (انتخاب بین صفحه‌ها حفظ می‌شود)، شمارهٔ سفارش، نام مشتری، تاریخ و ساعت شمسی، **وضعیت + زیرنویس درگاه پرداخت**، **قیمت دوخطی** (عدد بالا، واحد پولی فروشگاه زیرش) و ستون عملیات: «جزئیات»، «تغییر وضعیت» و «چاپ رسید».
- **تغییر وضعیت تکی و گروهی**: مودال تغییر وضعیت هم فقط **وضعیت‌های واقعی سایت** را پیشنهاد می‌دهد (بدون trash/auto-draft) و روی چند سفارش انتخاب‌شده به‌صورت گروهی با `PUT` اعمال می‌شود.
- **سه نوع رسید** با پیش‌نمایش میلی‌متری واقعی و چاپ از طریق پنجرهٔ چاپ ویندوز: **رسید فروشگاه** (فیش حرارتی عرض ۸ سانتی‌متر برای خرید حضوری)، **رسید پستی** (نوار ۲۱ × ۴٫۲ سانتی‌متر، نصف‌شده از وسط: گیرنده/فرستنده با کادر راه‌راه مورب) و **رسید انبارداری** (۱۰ × ۴٫۲ سانتی‌متر با ارتفاع متغیر برای اقلام و یادداشت‌های بیشتر؛ یادداشت‌های سیستمی چاپ نمی‌شوند و جملات «تنظیمات یادداشت سفارش» از چاپ حذف می‌شوند).
- پنل **جزئیات سفارش**: اقلام با مشخصات ترکیب/متغیر، کد تخفیف و هزینهٔ ارسال، مجموع اقلام و مبلغ نهایی (همه با واحد پولی فروشگاه)، مشخصات و آدرس مشتری، و **یادداشت‌های سفارش** با برچسب رنگی + فرم «ثبت یادداشت» (خصوصی/برای مشتری با ارسال ایمیل).

### ثبت سفارش سریع

- ثبت سفارش حضوری در چند گام: **تشخیص آنی مشتری از شمارهٔ موبایل** (مقایسهٔ هوشمند ارقام فارسی/لاتین با کش مشتریان — بدون درخواست اضافه)، ساخت مشتری جدید در صورت نبود، انتخاب محصول (ساده یا **متغیر با ترکیب‌ها**) و تعداد، و ثبت سفارش با وضعیت دلخواه.
- سفارش سریعِ حضوری (`sale-hazouri`) بلافاصله در **انبارِ سفارش‌سریع** تخصیص موجودی می‌شود.
- مبلغ سفارش در «لاگ تغییرات» با فیلد **amount** ثبت می‌شود تا آمار پیشخوان دقیق باشد.

### محصولات

- فهرست محصولات **در همهٔ وضعیت‌ها** (منتشرشده، خصوصی، پیش‌نویس، در انتظار) با عکس، **قیمت دوخطی** (قیمت حراج با خط‌خورده + قیمت جاری)، وضعیت موجودی، تعداد فروش و دسته‌بندی؛ **نام محصول همیشه کامل دیده می‌شود** (ستون تاریخ ایجاد برای باز شدن جا حذف شده) و جدول بدون اسکرول افقی است.
- **ویجت‌های آماری** (کل/موجود/ناموجود/فروش کل) روی همهٔ صفحه‌ها محاسبه و کلیک‌پذیرند (فیلتر زندهٔ فهرست).
- «افزودن محصول» (ساده/متغیر) و ستون عملیات آیکنی: **جزئیات و ویرایش ترکیبات** (قیمت، حراج، موجودی و وضعیت هر ترکیب با `PUT`)، **سفارش‌های محصول** (بدون احتساب ناموفق/لغو/بازپرداخت)، **تغییر کلی قیمت** (درصدی با گرد شدن یا ثابت) و **تغییر کلی موجودی** روی همهٔ ترکیبات (با فعال‌سازی خودکار مدیریت موجودی).
- **قیمت تمام‌شدهٔ کالا** به ازای هر محصول در تنظیمات ثبت می‌شود و مبنای «سود ناخالص» در گزارشات است.

### انبارها (چندانباری)

- تعریف تا **۸ انبار** (کارگاه، فروشگاه، انبار سریع و…) در تنظیمات؛ هر انبار موجودی خود را در متای `_stock_{id}` محصول/ترکیب نگه می‌دارد.
- **ثبت موجودی توسط انباردار** به‌صورت تفکیکی برای هر انبار (محصولات متغیر: ثبت به تفکیک هر ترکیب) و نمایش «ثبت‌نشده/هماهنگ/مغایرت» برای هر قلم.
- **تخصیص خودکار**: هر انبار می‌تواند به یک وضعیت سفارش نگاشت شود؛ وقتی سفارشی به آن وضعیت برسد (تکی یا گروهی)، اقلامش به‌صورت خودکار از انبار کسر/تخصیص می‌شود و در صورت لغو/برگشت، موجودی برمی‌گردد.
- جدول مقایسهٔ **موجودی سایت ↔ مجموع انبارها** با ستون‌های فشرده و نشانِ **اقلام مغایرت‌دار** در سایدبار.

### گزارشات

- تحلیل چندبخشی در تب‌ها: **خلاصه** (فروش و درآمد با نمودار روزانه)، **مشتریان برتر**، **محصولات پرفروش**، **سفارش‌ها** و **موجودی** (با **حد نصاب موجودی** قابل تنظیم برای هشدار reorder).
- **سود ناخالص** بر مبنای قیمت تمام‌شدهٔ ثبت‌شده در تنظیمات؛ محدودهٔ تاریخ دلخواه (شمسی) و نمودار میله‌ای روزانه.

### لاگ تغییرات

- هر اکشن مهم (ثبت/تغییر وضعیت سفارش، ویرایش محصول/قیمت/موجودی، انبارداری، تغییر تنظیمات و…) با **نام کارشناس**، بخش، زمان شمسی، جزئیات، هدف و **مبلغ** ثبت می‌شود.
- **هویت کارشناس از خودِ کلید API** خوانده می‌شود: اول از مسیر `ping` افزونهٔ لاگ (همان امضای OAuth ثبت لاگ) و در نبودِ افزونه از `wp/v2/users/me` — بنابراین هر دستگاه/کاربر به نام خودش ثبت می‌کند.
- لاگ هم **محلی** (روی دستگاه، با جستجو و فیلتر کاربر/بخش/اکشن) نگهداری می‌شود و هم به‌صورت **مشترک روی سرور** (افزونهٔ «WC App Change Log») آینه می‌شود تا همهٔ دستگاه‌ها یک تاریخچه را ببینند.

### تنظیمات

- **اتصال به فروشگاه**: آدرس سایت + کلیدهای API با راهنمای گام‌به‌گامِ ساخت کلید، «تست اتصال» و ذخیرهٔ امن روی خود دستگاه؛ راهنمای API کنار فرم.
- **ظاهر برنامه** (جدید): انتخاب **تم تیره یا روشن** (تم روشن، مینیمال با پس‌زمینهٔ روشن و متن تیره) و **رنگ تأکیدی دستی** — هشت رنگ آماده یا انتخابگر رنگ دلخواه؛ تغییرات **فوراً پیش‌نمایش** می‌شوند و با ذخیره ماندگار می‌شوند. رنگ انتخابی در **هر دو تم** روی دکمه‌ها، منوی فعال، نمودارها و همهٔ عناصر تأکیدی اعمال می‌شود.
- **لوگوی شخصی**: از بخش «اطلاعات رسید» انتخاب می‌شود و **بالای سایدبار** (به‌جای کادر لوگوی پیش‌فرض) و روی رسیدهای پستی چاپ می‌شود؛ به‌صورت خودکار تا عرض ۵۰۰ پیکسل کوچک و به‌صورت data URL ذخیره می‌شود.
- **اطلاعات رسید**: نام، آدرس، کدپستی و تلفن پشتیبانی فروشگاه.
- **تنظیمات یادداشت سفارش**: جملاتی که یادداشت‌های حاوی آن‌ها روی رسید انبارداری چاپ نمی‌شوند.
- **انبارها**: تعریف انبارها، نگاشت وضعیت تخصیص و تعیین انبارِ سفارش سریع.
- **کش**: عمر کش فهرست‌ها/جزئیات/گزارش‌ها و سن مجاز کش در شروع دوبارهٔ برنامه (TTLهای قابل تنظیم).

### واحد پولی پویا

- **واحد پولی فروشگاه از طریق API خوانده می‌شود** (`/data/currencies/current` و در صورت نیاز `/settings/general/woocommerce_currency`) و کنار **همهٔ قیمت‌های برنامه** (سفارش‌ها، محصولات، مشتریان، گزارشات، پیشخوان، مودال‌ها و رسیدها) نمایش داده می‌شود — دیگر هیچ «تومان» سخت‌کدی وجود ندارد.
- نتیجه **یک ساعت کش** می‌شود و در قطعی موقت سایت، آخرین واحد موفق «چسبنده» باقی می‌ماند تا قیمت‌ها بدون واحد نمانند.

### کش و کارایی

- **کش لایه‌ای در فرایند اصلی**: خواندن‌های تکراری (مشتریان، سفارش‌ها، محصولات، آمار) از اسنپ‌شات کش سرو می‌شوند؛ **همگام‌سازی افزایشی** سفارش‌ها (فقط سفارش‌های تغییر یافته از آخرین sync واکشی و در اسنپ‌شات وصله می‌شوند).
- **stale-while-revalidate**: نسخهٔ موجود فوراً نمایش داده و تازه‌سازی در پس‌زمینه انجام می‌شود؛ کش **روی دیسک** هم ذخیره می‌شود تا اجرای بعدی برنامه فوری باشد.
- نشان **«آخرین همگام‌سازی»** برای هر بخش و دکمهٔ «بارگذاری مجدد» برای بی‌اعتبارسازی دستی کش.
- فیلترها، جستجو و صفحه‌بندی سفارش‌ها کاملاً **محلی** روی اسنپ‌شات اعمال می‌شوند (بدون دانلود مجدد).

## افزونهٔ وردپرس (اختیاری ولی توصیه‌شده)

فایل `wordpress/wc-app-change-log.php` (نسخهٔ **۱٫۱**) را در `wp-content/plugins/` سایت آپلود و فعال کنید تا:

- لاگ تغییرات به‌صورت **مشترک بین همهٔ دستگاه‌ها** روی سرور ذخیره و خوانده شود؛
- **نام کارشناس** از طریق مسیر `ping` افزونه با همان امضای OAuth کلیدهای ووکامرس احراز شود (پایدارتر از `wp/v2/users/me` روی سایت‌های سخت‌گیر)؛
- فیلد **مبلغ** (amount) و **فیلتر action** در دسترس باشد (مبنای آمار سفارش‌های پیشخوان).

> افزونه فقط با کلیدهای API ووکامرس احراز هویت می‌شود و به لاگین وردپرس نیازی ندارد. بدون افزونه هم برنامه کار می‌کند — لاگ فقط محلی می‌ماند و هویت کارشناس از `wp/v2/users/me` خوانده می‌شود.

## ساخت کلید API در ووکامرس

1. در پیشخوان وردپرس: **ووکامرس ← تنظیمات ← پیشرفته ← REST API**.
2. **افزودن کلید**؛ دسترسی را برای استفادهٔ کامل (ثبت سفارش، تغییر وضعیت، ویرایش محصول و لاگ مشترک) روی **خواندن/نوشتن (Read/Write)** بگذارید و کاربر را **کاربر مدیر یا کارشناس موردنظر** انتخاب کنید (نام همان کاربر در لاگ و پیشخوان دیده می‌شود).
3. مقدارهای `Consumer Key` و `Consumer Secret` را کپی و در «تنظیمات» برنامه وارد کنید.
4. «ذخیره تنظیمات» و سپس «تست اتصال» را بزنید.

> پیش‌نیاز سایت: افزونهٔ ووکامرس نصب و فعال و API از مسیر `/wp-json/wc/v3` در دسترس باشد. با کلید **فقط خواندن** هم برنامه کار می‌کند اما نوشتن‌ها (ثبت سفارش/یادداشت/تغییر وضعیت/ویرایش محصول) رد می‌شوند.

## نکات فنی

> **فهرست مشتریان** از `wc/v2/customers` خوانده می‌شود نه `wc/v3` — چون نسخهٔ ۳ عمداً `orders_count` و `total_spent` را برنمی‌گرداند. بقیهٔ درخواست‌ها روی `wc/v3` می‌مانند.
>
> **وضعیت محصولات و REST:** API محصولات در هر درخواست فقط **یک** `status` می‌پذیرد؛ در حالت «همهٔ وضعیت‌ها» هر وضعیت موازی واکشی و در حافظه ادغام می‌شود (سقف ۱۰۰۰ محصول برای هر وضعیت).
>
> **سفارش‌های یک محصول:** پارامتر `status` صریحاً فرستاده نمی‌شود (پیش‌فرض API همهٔ وضعیت‌هاست)؛ پس از دریافت، سفارش‌های ناموفق/لغو/بازپرداخت کنار گذاشته می‌شوند و همهٔ صفحه‌ها تا سقف ۲۰۰۰ سفارش خوانده می‌شود تا شمارش دقیق بماند.
>
> **مجموع خرید مشتری:** ووکامرس فقط سفارش‌های پرداخت‌شده را در `total_spent` می‌شمرد؛ برنامه مجموع را با احتساب **همهٔ وضعیت‌ها به‌جز ناموفق، لغو و بازپرداخت** محاسبه می‌کند.
>
> **ویجت‌های سراسری مشتریان** با پیمایش همهٔ مشتریان در پس‌زمینهٔ فرایند اصلی (با محدودیت همزمانی) محاسبه می‌شوند؛ اولین محاسبه در فروشگاه‌های بزرگ چند دقیقه طول می‌کشد و پس از آن تا پایان نشست فوری است.
>
> **چاپ رسید:** رسیدها سندهای HTML مستقل با `@page` میلی‌متری هستند؛ چاپ از طریق IPC به یک پنجرهٔ مخفی و `webContents.print` با حاشیهٔ صفر انجام می‌شود (با کلید فقط‌خواندن هم ممکن است). در پنجرهٔ چاپ باید اندازهٔ منطبق انتخاب شود (۲۱۰×۴۲، ۱۰۰×۴۲ یا عرض ۸۰ میلی‌متر).
>
> **امنیت:** کلیدها فقط در پوشهٔ کاربر (userData) همین دستگاه ذخیره و هرگز از برنامه خارج نمی‌شوند؛ امضای درخواست‌ها با OAuth 1.0a (HMAC-SHA1) است و کلیدها در URL ساده ارسال نمی‌شوند.
>
> **تم و رنگ:** توکن‌های طراحی (رنگ پس‌زمینه، جوهر، خطوط، سایه‌ها و خانوادهٔ رنگ تأکیدی) به‌صورت متغیرهای CSS تعریف شده‌اند؛ تم روشن همهٔ توکن‌ها را یک‌جا بازنویسی می‌کند و رنگ تأکیدی انتخابی (با مشتقات روشن/تیره/نرم و کنتراست خودکار متن) به‌صورت متغیرهای درون‌خطی روی ریشهٔ سند اعمال می‌شود تا در هر دو تم یکسان کار کند.

## اجرا در حالت توسعه

```bash
npm install
npm run dev
```

این دستور Vite و پنجرهٔ Electron را با بارگذاری داغ (HMR) اجرا می‌کند. تغییرات فرایند اصلی (main/preload) نیاز به ساخت دوباره دارد:

```bash
npm run typecheck          # بررسی تایپ‌ها
npx tsc -p tsconfig.node.json   # ساخت فرایند اصلی
```

## ساخت خروجی (تست بدون نصب)

npm run dist:dir

فایل اجرایی در `release/win-unpacked/` ساخته می‌شود.

## ساخت نصاب ویندوز

```bash
npm run dist
```

خروجی: `release/WooCommerce-Dashboard-Setup-1.1.0.exe` (نصاب NSIS؛ امکان انتخاب مسیر نصب).

**نکته:** نصاب امضای دیجیتال ندارد، بنابراین هنگام اجرا ممکن است SmartScreen ویندوز هشدار دهد → «اطلاعات بیشتر ← اجرا به هر حال».

### اگر دانلود ابزارهای بسته‌بندی از GitHub قطع شد

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ \
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ \
npx electron-builder
```

اگر خطای `EPERM` هنگام استخراج Electron در بسته‌بندی دیدید (تداخل آنتی‌ویروس با rename)، از نسخهٔ آمادهٔ Electron استفاده کنید:

```bash
npx electron-builder --config.electronDist=node_modules/electron/dist
```

## ساختار پروژه

```
src/
  main/        فرایند اصلی Electron (پنجره، تنظیمات، کلاینت REST + OAuth، کش دیسک/حافظه، لاگ، موتور انبارها)
  preload/     پل امن (contextIsolation) بین رابط و فرایند اصلی
  shared/      تایپ‌ها، واحد پولی و منطق مشترک انبارها/تلفن
  renderer/    رابط کاربری React (فارسی/راست‌چین) + فونت وزیرمتن
    lib/       قالب‌بندی فارسی/شمسی، واحد پولی، تم و دادهٔ آزمایشی
    components/ نمای‌ها (پیشخوان، سفارش‌ها، محصولات، انبارها، گزارشات، لاگ، تنظیمات) و مودال‌ها
    styles/    توکن‌های طراحی و همهٔ استایل‌ها (تم تیره/روشن)
wordpress/     افزونهٔ «WC App Change Log» (لاگ مشترک سمت سرور)
scripts/       تولید آیکون برنامه (بدون وابستگی خارجی)
build/         آیکون‌های برنامه (icon.png / icon.ico)
```
